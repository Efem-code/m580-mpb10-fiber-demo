Automation · Bench build guide

Modicon M580 ↔ SICK MPB10, with a fiber RIO ring

How to wire and set up the demo board: a Modicon M580 safety CPU (BMEP584040S with its BMEP58CPROS3 coprocessor) and a BMENOC0311, with its BMECRA31210 RIO drop linked over multimode fiber by a pair of BMXNRP0200s. The NOC scans a SICK SIG300 IO-Link master with a Multi Physics Box (MPB10) and an ATV930 running the motor. We follow the sections in order and end with live vibration, shock and temperature values in Control Expert and on the dashboard.

1What we’re building

Copper Ethernet Multimode fiber (RIO ring) IO-Link (M12 A-coded) Drive / motor power Safety modules (SAFE task, not used here)
Two networks and a fiber ring. The RIO ring leaves the CPU on ETH2 and ETH3, goes through the main rack’s BMXNRP0200, over two multimode fiber links to the drop’s BMXNRP0200, and on to the BMECRA31210. Pull one fiber and the drop keeps running on the other path. The BMENOC0311 scans the ATV930 and the SIG300 on the device network (192.168.20.x, the NOC’s backplane port disabled); the CPU, the drop and the laptop are on the control network (192.168.10.x). The PLC is the only thing that joins them.

3IP plan

Two networks, both mask 255.255.255.0 and neither with a gateway. Give the SIG300 its new address first (section 5).

The rig reuses 192.168.10.x and 192.168.20.x, which the lab network uses too. Keep the rig on its own cables and switches and never patch it into the lab network, or addresses like .10 will clash. The cobot’s D-Link router is the exception: it joins the device network on purpose (section 4).

4Hardware build

Racks and RIO ring

  1. With the power off, check every module is seated and its screws torqued. The coprocessor must stay in the slot right of the CPU.
  2. Main rack: CPU ETH2 and ETH3 to the two copper ports of the main rack’s BMXNRP0200. Keep the CPU service port (ETH1) for the laptop.
  3. Drop: BMECRA31210 ETH2 and ETH3 to the two copper ports of the drop’s BMXNRP0200. Set the CRA rotary switches to drop 3 (tens 0, ones 3) with its power off.
  4. Fiber: the two duplex links between the NRPs’ fiber ports. Clean each LC ferrule with a one-click cleaner before plugging in; most “no link” faults are dirty ends. Tx must land on Rx: standard A–B duplex cords already cross over; if a link stays dark, flip the two simplex connectors at one end only. Keep bends gentler than about a 30 mm radius.
  5. Leave the racks powered off until the CPU is configured (section 6).
Never look into a live fiber or port. The light is invisible. Use a fiber microscope or visual fault locator to check an end.

Drive

  1. Check the drive supply: the ATV930U07M3 needs 200–240 V three-phase on L1/L2/L3, through the breaker sized in its installation manual.
  2. Run the motor cable (shielded, 360° bonded at both ends) to the motor.
  3. Patch the ATV930’s embedded Ethernet port to BMENOC0311 ETH2.
  4. Wire the E-stop to the STO inputs. Set up the drive on its keypad as in the Control Expert guide, section 2.

SIG300 and MPB10

  1. DIN-mount the SIG300 and wire its 24 VDC power cable (pin-out and connector from its operating instructions).
  2. Patch BMENOC0311 ETH3 to one of the SIG300’s Ethernet ports with the RJ45-to-M12 cable.
  3. Bolt the MPB10 to the motor and run the M12 sensor cable to SIG300 port S1.

Wi-Fi and the cobot

  1. On the D-Link’s web page (http://192.168.20.1): LAN address 192.168.20.1 / 24, DHCP pool 192.168.20.150 to .199. Give the cobot a reservation at 192.168.20.94, or a fixed address in Cobot Expert.
  2. Patch one of the D-Link’s LAN ports to the BMENOC0311’s ETH1 service port. Leave its WAN port empty: it must not route the rig onto another network. The cobot stays cabled to the D-Link.
  3. A laptop on the D-Link’s Wi-Fi now reaches the SIG300, the ATV930 and the cobot web pages. If its internet stops working, the D-Link has become its default route: set a fixed address in the pool with no gateway on that Wi-Fi adapter.
  4. In the SIG300’s DTM, set the input connection to Point to Point like the ATV930’s, so multicast I/O doesn’t flood the Wi-Fi.

5Set up the SIG300 and MPB10

  1. Connect the laptop directly to the SIG300. Find its factory address on the label or in the operating instructions, put the laptop on the same subnet for now, and browse to it.
  2. Change the SIG300 IP to 192.168.20.20 / 255.255.255.0, no gateway. Save, set the laptop to 192.168.20.100 and reconnect at the new address. (Later, with the rack running, reach it through the D-Link’s Wi-Fi or the NOC’s ETH1 service port.)
  3. Set port S1 to IO-Link mode. The MPB10 should be listed with its vendor and device ID, and the port LED should show IO-Link communication.
  4. Load the MPB10 IODD into the SIG300 (if it isn’t built in) so its values show by name. Set the measurement mode and warning/alarm thresholds here or in SOPAS ET.
  5. Turn on Data Storage on port S1 so a replacement MPB10 gets the same settings.

6Program the M580 and run the dashboard

The Control Expert program and its step-by-step build live in m580-mpb-fiber\control-expert. Open Control-Expert-build-guide.html there. It covers the ATV930 keypad set-up, the safety project with its racks, the RIO drop over fiber and the BMENOC0311, the SIG300 and ATV930 in the DTM Browser, the seven ST sections (MPB10 decode, drive state machine, stack-light state, dashboard link, alarms), and the commissioning order. Our sections run in the normal MAST task; the SAFE task stays empty.

The customer screen is in m580-mpb-fiber\dashboard: run Start Dashboard.bat. It has tabs for machine health, alarms, the drive, VFD control (run the ATV930 through the M580), the network path, every IP address, and setup. Plug the laptop into the CPU service port (ETH1). Test the screen before the PLC is ready with python fake_m580.py.

The dashboard only reads the PLC unless “Allow drive control” is ticked in its Setup tab and the PLC sets xDashboardAllowed. A 1 s watchdog in the PLC stops the motor if the dashboard goes silent. The E-stop is hard-wired to the ATV930 STO inputs.

7Bring-up checklist

  • Racks power up, CPU RUN LED steady after download
  • Fiber link LEDs on at both BMXNRP0200s
  • RIO drop healthy; pull one fiber link and it stays healthy (ring status goes open), reconnect
  • Laptop on CPU ETH1 pings 192.168.10.10 and .20; on the D-Link Wi-Fi it pings 192.168.20.10, .20 and .30
  • SIG300 NS LED solid green; port S1 shows IO-Link communication
  • Device health bits TRUE in the animation table
  • Values change when we tap the motor; temperature reads close to room temperature at rest
  • Unplug the SIG300 cable: xSensorCommAlarm goes TRUE within a few RPIs. Reconnect and it clears
  • Clip on the weight: vibration rises and the warning bit trips
  • Dashboard in Live mode: heartbeat counting, every box on the network tab green, the CPU and drop reachable on the IP addresses tab (the device network shows “not from here”)
  • Drive runs from the animation table, then from the dashboard; the E-stop stops it regardless

8When it doesn’t work

SymptomCheck
No fiber link light on an NRPTx/Rx swapped: flip one end. Dirty ferrule: clean it. One strand broken or not seated: swap strands to see if the fault follows the strand.
RIO drop not healthyRotary switches don’t match the drop number in the project (set them with the power off), the ring patches in the wrong CPU or CRA ports, both fiber links down, or the drop’s IP clashes with another device.
Only one RIO port lit on the CPU or CRAThe ring is open: one patch or fiber link is missing. The drop still runs, but without redundancy.
No ping to the SIG300It is on the device network: ping it from the D-Link Wi-Fi or the NOC’s ETH1 service port with the laptop on 192.168.20.x, not from the CPU port. Then check it isn’t still at its factory address, and the mask.
Ping OK, health bit FALSEWrong EDS or SIG300 variant (PROFINET model), assembly mismatch, or IP in the DTM doesn’t match the device.
Data arrives but values look wrongByte order (swap high/low), wrong iPD_Ofs, or the MPB10 measurement mode doesn’t match the offsets we used.
MPB10 not found on S1Port not in IO-Link mode, cable not A-coded or too long (> 20 m), or the port is disabled in the SIG300.
Control Expert can’t create or open the projectA BMEP584040S needs the Safety (XLS) license. Check Help → About or the license manager.

9Confirm before the customer sees it

These came from photos, datasheets and distributor listings; check them against the official manuals and the units on the bench:
  • How the RIO ring is patched through the two BMXNRP0200s, and that pulling one fiber link leaves the drop running.
  • SIG300 order code really is the EtherNet/IP variant, its power pin-out, factory IP address and connectors, and where port S1’s process data sits in its EtherNet/IP input assembly.
  • MPB10 process-data layout, scaling and alarm-bit meanings (IODD / operating instructions).
  • The supply to the ATV930U07M3 is 200–240 V three-phase, and the motor nameplate (voltage, current 4.6 A or less, speed) suits it.
  • That PQI bit 7 means “process data valid” on port S1, and the Modbus unit ID the M580 answers on (255 or 0).
