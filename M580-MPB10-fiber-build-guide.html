Modicon M580 ↔ SICK MPB10 over fiber

How to wire and set up the demo rig: a SICK Multi Physics Box (MPB10) on a SICK SIG200 IO-Link master, linked to a Modicon M580 (BMEP584040 with BMENOC0301, BMENUA0100 and a BMECRA31210 RIO drop) over a multimode fiber run, with an ATV930 running the motor. Follow the sections in order and you end with live vibration, shock and temperature values in Control Expert.

1What you’re building

Copper Ethernet Multimode fiber IO-Link (M12 A-coded, unshielded OK) Drive / motor power 24 VDC
Three networks in one rig. The RIO ring (CPU ETH2 → drop → ETH3) carries the operator panel I/O and keeps running if one cable is pulled. The BMENOC0301 scans the ATV930 and, over the fiber, the SIG200. The NOC’s backplane port is enabled, so the laptop on the CPU service port sees every device. The BMENUA0100 control port is a separate network that only serves OPC UA. The drive is on the PLC side of the fiber, so pulling the fiber cuts the sensor data and the motor keeps running.

4Hardware build

PLC end

  1. With the power off, fit the PSU, CPU, BMENOC0301 and BMENUA0100 on the backplane. Torque the module screws.
  2. RIO ring: CPU ETH2 to one device port on the BMECRA31210, the CRA’s other device port back to CPU ETH3. Set the CRA rotary switches to drop 1 with its power off. Wire Start, Stop (N/C contact), Reset and the key switch to the drop’s inputs, the stack light to its outputs.
  3. Patch BMENOC0301 ETH3 to media converter A in the panel. Keep the CPU service port (ETH1) for the laptop. The NOC’s own top port (ETH1) is also a service port: fine for the HMI or a second laptop, but not for the drive or the fiber.
  4. Leave the rack powered off until the CPU is configured (section 6).

Drive

  1. Check the drive supply: the ATV930U07M3 needs 200–240 V three-phase on L1/L2/L3, through the breaker sized in its installation manual.
  2. Mount the ATV930 in the PLC panel. Run the motor cable (shielded, 360° bonded at both ends) to the motor.
  3. Patch the ATV930’s embedded Ethernet port to BMENOC0301 ETH2. It stays on the PLC side of the fiber, so pulling the fiber cuts only the sensor data.
  4. Wire the E-stop to the STO inputs. Set up the drive on its keypad as in the Control Expert guide, section 2.

Fiber link

  1. Remove the dust caps only when you are ready to plug in. Clean each LC ferrule with a one-click cleaner. Most bench “no link” faults are dirty ends.
  2. Plug the duplex cord into media converter A (panel) and the other end into media converter B (field).
  3. Tx must land on Rx. Standard A–B duplex cords already cross over. If there is no link light later, flip the two simplex connectors at one end only.
  4. Dress the run in a loop or on the spool, no tighter than about a 30 mm bend radius. Put a label at each end.
Never look into a live fiber or port. At 1310 nm the light is invisible. Use a fiber microscope or visual fault locator to check an end.

Field end

  1. DIN-mount media converter B and the SIG200. Wire the 24 VDC supply to the converter terminals and the SIG200 power cable (check pin-out in the SIG200 manual: pin 1 +24 V, pin 3 0 V is typical for A-coded power).
  2. Connect the converter RJ45 to the SIG200 Ethernet port with the RJ45-to-M12 D-coded cable.
  3. Bolt the MPB10 to the motor and run the M12 sensor cable to SIG200 port S1.
  4. Power up the field end. Expect the converter’s power LED and the SIG200 power LED on. The fiber link LED stays off until converter A is powered.

5Set up the SIG200 and MPB10

  1. Connect the laptop directly to the SIG200 (or through the converter with the rack off). Set the laptop to 192.168.0.100 and browse to http://192.168.0.1.
  2. Change the SIG200 IP to 192.168.0.20 / 255.255.255.0, gateway 192.168.0.10. Save and reconnect at the new address.
  3. Set port S1 to IO-Link mode. The MPB10 should be listed with its vendor and device ID, and the port LED should show IO-Link communication.
  4. Load the MPB10 IODD into the SIG200 (if it isn’t built in) so its values show by name. Set the measurement mode and warning/alarm thresholds here or in SOPAS ET.
  5. Turn on Data Storage on port S1 so a replacement MPB10 gets the same settings (demo step 5).
  6. Note the SIG200’s EtherNet/IP assembly instances and where port S1’s process data starts in the input assembly. You need that byte offset in section 7.

6Program the M580 and run the dashboard

The Control Expert program and its step-by-step build live in m580-mpb-fiber\control-expert. Open Control-Expert-build-guide.html there. It covers the ATV930 keypad set-up, the rack, RIO drop and BMENOC0301 set-up, the SIG200 and ATV930 in the DTM Browser, OPC UA on the BMENUA0100, the six ST sections (MPB10 decode, drive state machine with the panel buttons, stack light, dashboard link), and the commissioning order.

The customer screen is in m580-mpb-fiber\dashboard: run Start Dashboard.bat. It has tabs for machine health, the drive, VFD control (run the ATV930 through the M580), the network path, every IP address, and setup. Plug the laptop into the CPU service port (ETH1) so the screen stays up when you pull the fiber; it then shows exactly where the data stops. Test the screen before the PLC is ready with python fake_m580.py.

The dashboard only reads the PLC unless “Allow drive control” is ticked in its Setup tab and the PLC sets xDashboardAllowed. A 1 s watchdog in the PLC stops the motor if the dashboard goes silent. The E-stop is hard-wired to the ATV930 STO inputs.

7Bring-up checklist

  • Rack powers up, CPU RUN LED steady after download
  • RIO drop healthy; pull one ring cable and it stays healthy (ring status goes open), reconnect
  • Panel buttons and key switch show in the animation table; each lamp lights when forced
  • FX link LED on at both media converters
  • Laptop on ETH1 pings .10, .11, .15, .20 and .30
  • SIG200 NS LED solid green; port S1 shows IO-Link communication
  • Device health bit TRUE in the animation table
  • Values change when you tap the motor; temperature reads close to room temperature at rest
  • Pull the fiber: xSensorCommAlarm goes TRUE within a few RPIs. Reconnect and it clears
  • Clip on the weight: vibration rises and the warning bit trips
  • Dashboard in Live mode: heartbeat counting, every box on the SIG200 & network tab green, every device reachable on the IP addresses tab
  • Drive runs from the animation table, then from the panel Start button, then from the dashboard; panel Stop stops a dashboard run; the E-stop stops it regardless
  • UaExpert on the BMENUA0100 control port browses the PLC variables

8When it doesn’t work

SymptomCheck
No fiber link light at either endTx/Rx swapped: flip one end. Dirty ferrule: clean it. Wrong converter: it must be 100BASE-FX at 1310 nm. A 1 Gb SFP or an 850 nm part will never link.
Link light on one end onlyOne strand broken or not seated. Swap strands to see if the fault follows the strand.
Fiber link up, no ping to SIG200SIG200 IP still at 192.168.0.1, wrong mask, or the BMENOC0301 backplane port is disabled (the laptop on ETH1 then can’t see the NOC’s devices).
RIO drop not healthyRotary switches don’t match the drop number in the project (set them with the power off), ring cables in the wrong CPU ports, or the drop’s IP clashes with another device.
Ping OK, health bit FALSEWrong EDS or SIG200 variant (PROFINET model), assembly mismatch, or IP in the DTM doesn’t match the device.
Data arrives but values look wrongByte order (swap high/low), wrong PD_OFS, or the MPB10 measurement mode doesn’t match the offsets you used.
MPB10 not found on S1Port not in IO-Link mode, cable not A-coded or too long (> 20 m), or the port is disabled in the SIG200.

9Confirm before the customer sees it

These came from datasheets and distributor listings; check them against the official manuals for the units on the bench:
  • SIG200 order code really is the EtherNet/IP variant, and its power pin-out.
  • MPB10 process-data layout, scaling and alarm-bit meanings (IODD / operating instructions).
  • The two media converters match: 100BASE-FX, multimode, 1310 nm, same connector, and the link budget covers the cord length you bring.
  • Which X80 I/O modules are on the drop and which channel each button and lamp uses. On our board: the second module with rotary switches next to the CRA, and the wired I/O module.
  • The supply to the ATV930U07M3 is 200–240 V three-phase, and the motor nameplate (voltage, current 4.6 A or less, speed) suits it.
  • BMENUA0100 firmware, mode selector setting, and default login (Schneider FAQ FA405101).
  • Which SIG200 input-assembly bit means “device present on S1”, and the Modbus unit ID the M580 answers on (255 or 0).
