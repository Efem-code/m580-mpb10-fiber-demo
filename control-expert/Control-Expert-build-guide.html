Automation · Control Expert build

Programming the M580 for the demo rig

How to build the EcoStruxure Control Expert project for the rig: a BMEP584040 CPU with a BMENOC0301 scanning the SIG300 and the ATV930, a BMENUA0100 serving OPC UA, and a BMECRA31210 eRIO drop carrying the operator panel I/O. The program reads the SICK MPB10, runs the ATV930, drives the stack light and talks to the Machine Health dashboard. The program is six Structured Text sections in this folder; this page is the order to put them together and test them.

Safety first. The E-stop is hard-wired to the ATV930’s STO inputs and never goes through the PLC or the dashboard. Guard the motor and the unbalance weight. Test every drive step with the motor uncoupled and a low speed limit (iMaxSpeed).

1What’s in the folder

00_IO_Map→01_MPB10_Decode→02_Dashboard_In→03_ATV930_Control→04_Dashboard_Out→05_IO_Out

All six run in the MAST task, in that order. Only the two orange sections name the device DDTs Control Expert generates (SIG300, ATV930, and the X80 modules on the RIO drop), so they are the only ones we edit for our project. The others work on plain variables.

FileDoes
00_IO_Map.stCopies the SIG300 and ATV930 device-DDT inputs (health bits, input bytes, ETA, RFRD, LCR, OTR, THR, LFT) and the RIO drop inputs (drop health, ring status, Start, Stop, Reset, key switch) into plain variables. Ships “unmapped” (health FALSE) so it compiles and nothing runs.
01_MPB10_Decode.stTurns the 20 IO-Link bytes into mm/s, °C and alarm bits. Adds PLC-side limits and a shock counter. Zeroes everything when the sensor data is lost.
02_Dashboard_In.stReads the dashboard command block at %MW1100 and runs a 1 s heartbeat watchdog.
03_ATV930_Control.stOne run latch for three sources (panel, dashboard, animation table): last Start wins, any Stop wins. CiA402 state machine builds CMD and the speed reference.
04_Dashboard_Out.stWorks out the stack light and fills the status block at %MW1000 for the dashboard (word 29 = panel and RIO bits, words 30–31 = ramps in use).
05_IO_Out.stWrites CMD and LFRD into the ATV930 device DDT and the three lamps to the X80 outputs on the drop.
variables.csvEvery variable: name, type, located address, initial value, comment. Open it in Excel next to the Data Editor.

2Set up the ATV930 first

Do this on the drive’s keypad before the PLC gets involved. Menu names below are from the ATV900 family manuals; check them against our keypad. Our drive is an ATV930U07M3: 0.75 kW / 1 HP, 200–240 V three-phase in, 4.6 A out.

  1. Supply: 200–240 V three-phase on L1/L2/L3. It won’t run from a 120 V outlet.
  2. Motor: enter the nameplate data (power, voltage, current, frequency, speed), then run autotune. The motor’s full-load current must be 4.6 A or less. In North America that’s usually 60 Hz and about 1750 rpm for a 4-pole motor. Jog the motor from the keypad to prove the power side.
  3. Embedded Ethernet: Communication → Embedded Ethernet: IP mode Fixed, IP 192.168.20.30, mask 255.255.255.0, no gateway (or 192.168.20.10, the NOC). Power-cycle the drive so the address takes.
  4. Command and reference: Ref Freq 1 Config [Fr1] = Embedded Ethernet; Control mode [CHCF] = Not separate. That gives the CiA402 (Drivecom) profile this program uses.
  5. Local / Remote: the keypad’s LOCAL/REMOTE key must be on Remote. In Local the keypad owns the drive and the M580 can’t run it, which is the usual “it won’t start” on the day.
  6. Comms-loss response: set the Embedded Ethernet fault response to ramp stop or freewheel, so a cut cable stops the motor.
  7. STO: wire the E-stop to the STO inputs as the ATV930 safety manual shows. Confirm the drive shows “STO” when the E-stop is pressed.

The PLC is the only thing joining them: the NOC hands the drive and sensor data to the CPU across the rack, and the NUA serves it to IT. Nothing routes between the networks. The dashboard’s IP addresses tab holds the same plan; change it there and here together.

The rig reuses 192.168.10.x and 192.168.20.x, which the lab network uses too. Keep the rig on its own cables and switches and never patch it into the lab network, or addresses like .10 will clash.
  1. New project: BMEP584040. On the main rack add the power supply, BMENOC0301 and BMENUA0100 in their real slots.
  2. CPU → IPConfig: main IP 192.168.10.10, mask 255.255.255.0, no gateway. Leave the service port (ETH1) enabled in access mode: that’s where the dashboard laptop plugs in.
  3. Add the RIO drop to the PLC bus (EIO bus): a BME (Ethernet) or BMX rack matching yours, the BMECRA31210, then each X80 I/O module in its real slot. Drop number 1, IP 192.168.10.15 on the drop’s IPConfig (the drop is on the CPU’s control network). Set the CRA’s rotary switches to drop 1 (tens 0, ones 1) with the power off. The CPU hands the CRA its address at power-up.
  4. Assign the drop to the MAST task (the default), so its I/O is read and written in the same scan as the sections.
  5. BMENOC0301 → open its DTM: IP 192.168.20.10, mask 255.255.255.0, and disable the backplane port. With it enabled the NOC must share the CPU’s subnet, so Control Expert rejects .20.10. The drive and sensor still work: the NOC passes their I/O to the CPU across the rack, not over Ethernet. The laptop on CPU ETH1 can’t reach the SIG300 or ATV930 web pages any more; plug into the NOC’s ETH1 service port with a 192.168.20.x address for that.
  6. BMENUA0100: backplane address 192.168.10.12, control port 192.168.30.10. Section 7 covers the OPC UA side.
  7. Check the project allows located %MW memory with at least %MW1000–%MW1104 free (CPU configuration / project settings).

4Add the devices in the DTM Browser

SICK SIG300

  1. Check the SIG300’s type label: we need the EtherNet/IP model, SIG300-0A05AA100 (part no. 1131012), which has an EDS file. (The PROFINET and EtherCAT models can’t be scanned by the M580.)
  2. Get the EDS: sick.com → search the part number on the label → product page → Downloads → device description files → the EtherNet/IP EDS (a .zip with an .eds and an .ico). The SICK Support Portal has the same files. Unzip it into a folder of its own.
  3. DTM Browser → right-click the BMENOC0301 → Add EDS to library (or Tools → Hardware Catalog → EDS wizard) → browse to the .eds and finish.
  4. DTM Browser → right-click the BMENOC0301 → Add → SIG300. Alias SIG300. (Both devices hang off the NOC, not the CPU’s embedded scanner.)
  5. Address Setting: IP 192.168.20.20, mask 255.255.255.0 (static, matches the SIG300 web UI). RPI 50 ms.
  6. Pick the connection that carries the IO-Link port data. Note which input bytes hold port S1: that becomes iPD_Ofs.

Altivar ATV930

  1. Add the ATV930 under the same BMENOC0301, using the Altivar DTM from the Schneider DTM library (or the ATV930 EDS). Alias ATV930, IP 192.168.20.30, mask 255.255.255.0.
  2. Open the drive’s Protocols & Drive Profiles page:
    • EtherNet Protocol: EtherNet/IP.
    • IO Connection Profile: 100/101 Generic Altivar. It lets us choose the channels. (The 106/107 ATV9xx Solution profile has a fixed list without THR, LFT or ACC/DEC, and it writes torque, logic-output and analog-output values our program never sets.)
    • Fallback Mode: Freewheel stop, so the motor coasts to a stop if the PLC connection drops.
    • RPI 10 ms for both directions. Input Mode: Point to Point. Multicast drive data would be copied out of the NOC’s built-in switch and down the fiber as well.
  3. Drive I/O Profile: click the Code cell of each row and pick the parameter.
    ChannelInputs (drive to controller)Outputs (controller to drive)
    1ETA status word (3201)CMD command word (8501)
    2RFRD output speed, rpm (8604)LFRD speed reference, rpm (8602)
    3LCR motor current, 0.1 A (3204)ACC acceleration, 0.1 s (9001), optional
    4OTR motor torque, % (3205)DEC deceleration, 0.1 s (9002), optional
    5THR motor thermal state, % (3209)
    6LFT last fault (7121)
    The numbers in brackets are the Altivar logical addresses; if the drop-down shows different ones, use those. Without ACC/DEC the drive keeps the ramps set on its keypad and the VFD control tab can’t change them. Worth adding as inputs 7 and 8 later: EPRW (active electrical power, for an energy talking point) and CCC (active command channel, which shows a drive stuck in Local).
  4. Build → Analyze. Control Expert generates a device DDT for each device. Open the Data Editor and expand SIG300 and ATV930 to see the element names we need in section 6.

5Variables and sections

Set iPanelSpeed (speed when started from the panel Start button) and leave xPB_StopNC at its initial value TRUE.

  1. Data Editor → Variables: create every row in variables.csv. Give aDash the address %MW1000 and aCmd %MW1100, and set the initial values shown (limits, iMaxSpeed, the placeholders).
  2. Program → Tasks → MAST → Sections: create six ST sections with the file names, in order 00 to 05.
  3. Paste each file’s text into its section. Build → Analyze. It should compile with zero errors before we map anything.

6Map the devices

Open 00_IO_Map and replace each right-hand side marked EDIT with the device-DDT element:

xSIG300_Health := SIG300.Freshness;          (* example: use the names our Data Editor shows *)
aSIG300_In[iMapIdx] := SIG300.Inputs.Data[iMapIdx];
xATV_Health    := ATV930.Freshness;
wATV_ETA       := INT_TO_WORD(ATV930.Inputs.ETA);
iATV_Speed     := ATV930.Inputs.RFRD;

The RIO drop, in the same section. X80 discrete modules give device DDTs whose channels are DIS_CH_IN[n].VALUE and DIS_CH_OUT[n].VALUE:

xDrop_Health := ...;                          (* the drop's health bit *)
xRing_Closed := ...;                          (* CPU DDT: RIO main ring redundancy OK; then set xRingDiagMapped TRUE *)
xPB_Start    := DI_Module.DIS_CH_IN[0].VALUE;  (* use our module's instance name *)
xPB_StopNC   := DI_Module.DIS_CH_IN[1].VALUE;  (* N/C contact *)
xPB_Reset    := DI_Module.DIS_CH_IN[2].VALUE;
xKeySwitch   := DI_Module.DIS_CH_IN[3].VALUE;
xDemoEnable  := xKeySwitch AND xDrop_Health;  (* uncomment once the key switch is wired *)

Then uncomment and edit the lines in 05_IO_Out so CMD and LFRD reach the drive and the lamps reach the stack light. Build, then download over USB (first time) or ETH1.

The Stop push-button is a normal control stop, not an E-stop. Use an N/C contact so a broken wire stops the motor. The E-stop stays on the ATV930 STO inputs.
The MPB10 offsets and scaling (iVal1_Ofs, iVal2_Ofs, rVal1_Gain, rVal2_Gain) are placeholders. Take them from the MPB10 IODD for the measurement mode we set on the sensor. Until then the vibration and temperature numbers are not meaningful.

7OPC UA on the BMENUA0100 · the IT side

This is the part of the demo for IT and management: the same live machine data reaching a separate IT network over secure OPC UA, with no route from that network back to the drive or the sensor. The dashboard laptop plays the IT client through a USB Ethernet adapter, and its IT side · OPC UA tab shows the values arriving both ways, side by side.

Network

PortAddressNotes
BMENUA0100 control port192.168.30.10 / 24No gateway. Kept apart from the rig’s control (192.168.10.x) and device (192.168.20.x) networks, and from typical office Wi-Fi (192.168.1.x).

Plug the USB adapter into the NUA control port directly, or through a small unmanaged switch if a second client (UaExpert on another laptop) joins in.

In Control Expert

  1. BMENUA0100 in its real slot. IP configuration: backplane side 192.168.10.12; control port 192.168.30.10, mask 255.255.255.0, no gateway.
  2. Project Settings → General → PLC embedded data: tick Data dictionary, so the module can browse the PLC variables.
  3. In the Data Editor, tick the HMI column for the variables the dashboard looks for: iHeartbeat, rVibVelocity, rTemperature, xVibWarning, xVibAlarm, xTempWarning, iShockCount, iATV_Speed, iATV_SpeedRef, iATV_Current, xATV_Running, xATV_Fault, xDrop_Health, iRunSource. Also tick xDemoEnable: the dashboard’s write test tries it (it writes back the value it already holds, so nothing changes).
  4. Don’t expose the dashboard command block (aCmd) or anything that starts the motor. The IT side is for reading.
  5. Build, download, and check the NUA’s status LEDs.

First test: Standard mode

  1. Set the module’s mode selector to Standard (power-cycle after changing it).
  2. Dashboard → IP addresses: BMENUA0100 control port 192.168.30.10, laptop USB adapter 192.168.30.100. The tab’s check column should show the control port answering on TCP 4840.
  3. Dashboard → Setup → IT side: Security None, user blank (or the default account from FAQ FA405101). Save.
  4. IT side · OPC UA tab → Connect. Expect “14 of 14” variables found and the two value columns matching.

For the customer: Secured mode

  1. Set the mode selector to Secured. Change the default password on first login, and create an OPC UA user for the dashboard (for example itviewer) with read-only access.
  2. Dashboard → Setup → IT side: Security Basic256Sha256 · Sign & encrypt, that user and password. Save, then Connect.
  3. The first attempt is rejected: the module doesn’t trust our certificate yet. On the NUA’s certificate management, move the dashboard’s certificate (M580 demo dashboard, urn:guillevin:m580-demo:dashboard) from rejected to trusted, then Connect again. The certificate is made on first use in dashboard\opcua-pki\; keep that folder, or the module will have to trust a new one.
  4. Press Try a write from the IT side. It should be refused: that is the point to make. If it’s accepted, tighten the user’s role or the variable’s access before showing it.

Rehearse without the module

Run python fake_nua.py in the dashboard folder (needs python -m pip install asyncua): a stand-in NUA with the same variables, read-only, offering None and Sign & encrypt (user demo / demo). Set the control port to 127.0.0.1 on the IP addresses tab and Connect. With --plc 127.0.0.1:5020 it reads fake_m580.py over Modbus instead, so the two columns really come by two separate paths.

8Commission it, in this order

RIO drop and panel

  1. Power the drop. The CRA should take its address and xDrop_Health go TRUE. Press each button and turn the key: watch xPB_Start, xPB_StopNC (goes FALSE when pressed), xPB_Reset, xKeySwitch.
  2. Force each lamp from an animation table, then release the forces.
  3. Pull one ring cable: the drop stays healthy and xRing_Closed goes FALSE. Reconnect. Pull both: xDrop_Health goes FALSE and a panel-started run stops.

Sensor

  1. Animation table: xSIG300_Health TRUE. Watch aSIG300_In and tap the motor: the bytes that move are the MPB10’s. Set iPD_Ofs so byte 0 of the 20 lines up with them.
  2. Fill in the IODD offsets and gains. Check rTemperature reads room temperature at rest and rVibVelocity rises when we tap.
  3. Pull the fiber: xSensorCommAlarm TRUE and the values go to 0 within a second. Reconnect.

Drive (motor uncoupled, low speed)

  1. Set iMaxSpeed to 300 for the first run. xATV_Health must be TRUE and wATV_ETA must change when we press the E-stop.
  2. Set xDemoEnable TRUE, iLocalSpeed 200, then xLocalRun TRUE. Watch ETA go 16#0040 → 16#0021 → 16#0023 → 16#0027 and iATV_Speed follow the ramp.
  3. Set xLocalRun FALSE: the motor stops on its ramp. Try xLocalReverse. Press the E-stop while running: the motor must stop no matter what the PLC says.
  4. From the panel: key ON, press Start (runs at iPanelSpeed), press Stop. Turn the key OFF while running: it stops and won’t restart until Start is pressed again.
  5. Raise iMaxSpeed to the demo limit: the motor’s nameplate speed or lower (about 1750 rpm for a 60 Hz 4-pole motor). Set the dashboard’s Setup → speed limit and nominal speed to match.

Dashboard

  1. Dashboard → IP addresses tab: the CPU and RIO drop show reachable; the NOC, SIG300 and ATV930 show “not from here” (they’re on the device network) and their health bits on the network tab show whether they’re talking to the PLC. Setup → Mode Live. The heartbeat counts and all boxes on the network tab go green.
  2. To let the dashboard run the motor: tick Allow drive control in Setup, then set xDashboardAllowed TRUE in the PLC. The VFD control tab lists every permissive and shows which one is blocking.
  3. On the VFD control tab: Start forward, Stop, Start reverse, then hold Jog (the PLC caps it at iJogSpeedMax). Change the ramps and watch the reference-vs-actual chart.
  4. Run the demo sequence once with the motor uncoupled and a low iMaxSpeed. It uses the same command block as the buttons, so the PLC needs nothing extra. Check that STOP, the panel Stop and the E-stop each end it.
  5. Close the dashboard page while the motor runs: the PLC watchdog drops the run command within about 1 s.

9Confirm on our hardware

  • Which X80 I/O modules are on the drop, their instance names, and which channel each button and lamp is wired to. On our board: the second module with rotary switches next to the CRA, and the wired I/O module.
  • ATV930U07M3 supply is 200–240 V three-phase, the keypad is on Remote, and the motor nameplate suits a 4.6 A drive.
  • The drop’s health bit and the CPU’s RIO main-ring status bit (element names in the Data Editor).
  • BMENOC0301 at 192.168.20.10 with its backplane port disabled builds without errors, and the drive and SIG300 health bits go TRUE.
  • BMENUA0100: firmware and Control Expert version, the mode selector, and how the HMI flag exposes variables on our version.
  • BMENUA0100 Secured mode on our firmware: where users, roles and certificate trust are managed, and how to make the dashboard’s user read-only so the write test is refused.
  • Device-DDT element names for the SIG300 and ATV930 (health/Freshness bits, input and output elements).
  • Which SIG300 bit means “device present / process data valid on S1”, and the S1 byte offset.
  • MPB10 IODD: value offsets, scaling, and alarm-bit meanings.
  • ATV930 keypad menu names, the comms-fault parameter, and whether LCR/OTR/THR/LFT (and ACC/DEC on the output side) fit in the drive’s cyclic exchange.
  • The Modbus unit ID the M580 answers on (the dashboard defaults to 255; try 0 if it gets no reply).
