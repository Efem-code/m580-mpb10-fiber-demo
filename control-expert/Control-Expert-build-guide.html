Automation · Control Expert build

Programming the M580 for the demo rig

How to build the EcoStruxure Control Expert project for the rig: a BMEP584040 CPU with a BMENOC0301 scanning the SIG200 and the ATV930, a BMENUA0100 serving OPC UA, and a BMECRA31210 eRIO drop carrying the operator panel I/O. The program reads the SICK MPB10, runs the ATV930, drives the stack light and talks to the Machine Health dashboard. The program is six Structured Text sections in this folder; this page is the order to put them together and test them.

Safety first. The E-stop is hard-wired to the ATV930’s STO inputs and never goes through the PLC or the dashboard. Guard the motor and the unbalance weight. Test every drive step with the motor uncoupled and a low speed limit (iMaxSpeed).

1What’s in the folder

00_IO_Map→01_MPB10_Decode→02_Dashboard_In→03_ATV930_Control→04_Dashboard_Out→05_IO_Out

All six run in the MAST task, in that order. Only the two orange sections name the device DDTs Control Expert generates (SIG200, ATV930, and the X80 modules on the RIO drop), so they are the only ones you edit for your project. The others work on plain variables.

FileDoes
00_IO_Map.stCopies the SIG200 and ATV930 device-DDT inputs (health bits, input bytes, ETA, RFRD, LCR, OTR, THR, LFT) and the RIO drop inputs (drop health, ring status, Start, Stop, Reset, key switch) into plain variables. Ships “unmapped” (health FALSE) so it compiles and nothing runs.
01_MPB10_Decode.stTurns the 20 IO-Link bytes into mm/s, °C and alarm bits. Adds PLC-side limits and a shock counter. Zeroes everything when the sensor data is lost.
02_Dashboard_In.stReads the dashboard command block at %MW1100 and runs a 1 s heartbeat watchdog.
03_ATV930_Control.stOne run latch for three sources (panel, dashboard, animation table): last Start wins, any Stop wins. CiA402 state machine builds CMD and the speed reference.
04_Dashboard_Out.stWorks out the stack light and fills the status block at %MW1000 for the dashboard (word 29 = panel and RIO bits, words 30–31 = ramps in use).
05_IO_Out.stWrites CMD and LFRD into the ATV930 device DDT and the three lamps to the X80 outputs on the drop.
variables.csvEvery variable: name, type, located address, initial value, comment. Open it in Excel next to the Data Editor.

2Set up the ATV930 first

Do this on the drive’s keypad before the PLC gets involved. Menu names below are from the ATV900 family manuals; check them against your keypad. Our drive is an ATV930U07M3: 0.75 kW / 1 HP, 200–240 V three-phase in, 4.6 A out.

  1. Supply: 200–240 V three-phase on L1/L2/L3. It won’t run from a 120 V outlet.
  2. Motor: enter the nameplate data (power, voltage, current, frequency, speed), then run autotune. The motor’s full-load current must be 4.6 A or less. In North America that’s usually 60 Hz and about 1750 rpm for a 4-pole motor. Jog the motor from the keypad to prove the power side.
  3. Embedded Ethernet: Communication → Embedded Ethernet: IP mode Fixed, IP 192.168.0.30, mask 255.255.255.0, gateway 192.168.0.10. Power-cycle the drive so the address takes.
  4. Command and reference: Ref Freq 1 Config [Fr1] = Embedded Ethernet; Control mode [CHCF] = Not separate. That gives the CiA402 (Drivecom) profile this program uses.
  5. Local / Remote: the keypad’s LOCAL/REMOTE key must be on Remote. In Local the keypad owns the drive and the M580 can’t run it, which is the usual “it won’t start” on the day.
  6. Comms-loss response: set the Embedded Ethernet fault response to ramp stop or freewheel, so a cut cable stops the motor.
  7. STO: wire the E-stop to the STO inputs as the ATV930 safety manual shows. Confirm the drive shows “STO” when the E-stop is pressed.

All device-side addresses are 192.168.0.x / 255.255.255.0. The dashboard’s IP addresses tab holds the same plan; change it there and here together.

  1. New project: BMEP584040. On the main rack add the power supply, BMENOC0301 and BMENUA0100 in their real slots.
  2. CPU → IPConfig: main IP 192.168.0.10, mask 255.255.255.0. Leave the service port (ETH1) in access mode so the laptop reaches the device network through it.
  3. Add the RIO drop to the PLC bus (EIO bus): a BME (Ethernet) or BMX rack matching yours, the BMECRA31210, then each X80 I/O module in its real slot. Drop number 1, IP 192.168.0.15 on the drop’s IPConfig. Set the CRA’s rotary switches to drop 1 (tens 0, ones 1) with the power off. The CPU hands the CRA its address at power-up.
  4. Assign the drop to the MAST task (the default), so its I/O is read and written in the same scan as the sections.
  5. BMENOC0301 → open its DTM: IP 192.168.0.11, and enable the backplane port so the NOC, the CPU and the laptop on ETH1 share one device network. (Disable it only if a customer wants the drive and sensor network isolated; the laptop then can’t reach the SIG200 or ATV930 through the CPU.)
  6. BMENUA0100: backplane address 192.168.0.12, control port 192.168.1.10. Section 7 covers the OPC UA side.
  7. Check the project allows located %MW memory with at least %MW1000–%MW1104 free (CPU configuration / project settings).

4Add the devices in the DTM Browser

SICK SIG200

  1. Tools → Hardware Catalog → add the SIG200 EDS file with the EDS wizard (download it from the SIG200 product page).
  2. DTM Browser → right-click the BMENOC0301 → Add → SIG200. Alias SIG200. (Both devices hang off the NOC, not the CPU’s embedded scanner.)
  3. Address Setting: IP 192.168.0.20 (static, matches the SIG200 web UI). RPI 50 ms.
  4. Pick the connection that carries the IO-Link port data. Note which input bytes hold port S1: that becomes iPD_Ofs.

Altivar ATV930

  1. Add the ATV930 under the same BMENOC0301, using the Altivar DTM from the Schneider DTM library (or the ATV930 EDS). Alias ATV930, IP 192.168.0.30, RPI 20 ms.
  2. In the drive’s I/O scanning set-up, exchange these parameters:
    DirectionParameters
    PLC → driveCMD command word, LFRD speed reference (rpm). Optional: ACC and DEC ramp times, so the VFD control tab can change them (units follow the drive’s ramp increment Inr, 0.1 s by default).
    Drive → PLCETA status word, RFRD output speed, LCR motor current, OTR torque, THR motor thermal state, LFT last fault
    If the drive’s scanner can’t carry all six inputs, keep ETA and RFRD cyclic and leave the others at 0. The dashboard shows “–” for them.
  3. Build → Analyze. Control Expert generates a device DDT for each device. Open the Data Editor and expand SIG200 and ATV930 to see the element names you need in section 6.

5Variables and sections

Set iPanelSpeed (speed when started from the panel Start button) and leave xPB_StopNC at its initial value TRUE.

  1. Data Editor → Variables: create every row in variables.csv. Give aDash the address %MW1000 and aCmd %MW1100, and set the initial values shown (limits, iMaxSpeed, the placeholders).
  2. Program → Tasks → MAST → Sections: create six ST sections with the file names, in order 00 to 05.
  3. Paste each file’s text into its section. Build → Analyze. It should compile with zero errors before you map anything.

6Map the devices

Open 00_IO_Map and replace each right-hand side marked EDIT with the device-DDT element:

xSIG200_Health := SIG200.Freshness;          (* example: use the names your Data Editor shows *)
aSIG200_In[iMapIdx] := SIG200.Inputs.Data[iMapIdx];
xATV_Health    := ATV930.Freshness;
wATV_ETA       := INT_TO_WORD(ATV930.Inputs.ETA);
iATV_Speed     := ATV930.Inputs.RFRD;

The RIO drop, in the same section. X80 discrete modules give device DDTs whose channels are DIS_CH_IN[n].VALUE and DIS_CH_OUT[n].VALUE:

xDrop_Health := ...;                          (* the drop's health bit *)
xRing_Closed := ...;                          (* CPU DDT: RIO main ring redundancy OK; then set xRingDiagMapped TRUE *)
xPB_Start    := DI_Module.DIS_CH_IN[0].VALUE;  (* use your module's instance name *)
xPB_StopNC   := DI_Module.DIS_CH_IN[1].VALUE;  (* N/C contact *)
xPB_Reset    := DI_Module.DIS_CH_IN[2].VALUE;
xKeySwitch   := DI_Module.DIS_CH_IN[3].VALUE;
xDemoEnable  := xKeySwitch AND xDrop_Health;  (* uncomment once the key switch is wired *)

Then uncomment and edit the lines in 05_IO_Out so CMD and LFRD reach the drive and the lamps reach the stack light. Build, then download over USB (first time) or ETH1.

The Stop push-button is a normal control stop, not an E-stop. Use an N/C contact so a broken wire stops the motor. The E-stop stays on the ATV930 STO inputs.
The MPB10 offsets and scaling (iVal1_Ofs, iVal2_Ofs, rVal1_Gain, rVal2_Gain) are placeholders. Take them from the MPB10 IODD for the measurement mode you set on the sensor. Until then the vibration and temperature numbers are not meaningful.

7OPC UA on the BMENUA0100

This shows the same PLC data reaching an IT/SCADA network through a secure, separate port, with no route from that network to the drive or sensor.

  1. Project Settings → General → PLC embedded data: tick Data dictionary, so the module can browse the PLC variables.
  2. Expose the variables you want to show (for example rVibVelocity, rTemperature, iATV_Speed, xVibAlarm). In the Data Editor, the HMI column marks a variable as visible to OPC UA.
  3. The module’s operating mode (Standard or Secured) is chosen on the module itself. Standard is quickest for a first test. Secured is the one to show a customer: certificates, user accounts, signed and encrypted sessions.
  4. On a second laptop at 192.168.1.100, plug into the NUA control port and open UaExpert: opc.tcp://192.168.1.10:4840. Browse to the variables and drag them into the data view.
Schneider’s FAQ FA409424 has a video of a BMENUA0100 configured in Control Expert and read with UaExpert in Standard mode. The default account differs by mode; it’s in FAQ FA405101. Change it on first login.

8Commission it, in this order

RIO drop and panel

  1. Power the drop. The CRA should take its address and xDrop_Health go TRUE. Press each button and turn the key: watch xPB_Start, xPB_StopNC (goes FALSE when pressed), xPB_Reset, xKeySwitch.
  2. Force each lamp from an animation table, then release the forces.
  3. Pull one ring cable: the drop stays healthy and xRing_Closed goes FALSE. Reconnect. Pull both: xDrop_Health goes FALSE and a panel-started run stops.

Sensor

  1. Animation table: xSIG200_Health TRUE. Watch aSIG200_In and tap the motor: the bytes that move are the MPB10’s. Set iPD_Ofs so byte 0 of the 20 lines up with them.
  2. Fill in the IODD offsets and gains. Check rTemperature reads room temperature at rest and rVibVelocity rises when you tap.
  3. Pull the fiber: xSensorCommAlarm TRUE and the values go to 0 within a second. Reconnect.

Drive (motor uncoupled, low speed)

  1. Set iMaxSpeed to 300 for the first run. xATV_Health must be TRUE and wATV_ETA must change when you press the E-stop.
  2. Set xDemoEnable TRUE, iLocalSpeed 200, then xLocalRun TRUE. Watch ETA go 16#0040 → 16#0021 → 16#0023 → 16#0027 and iATV_Speed follow the ramp.
  3. Set xLocalRun FALSE: the motor stops on its ramp. Try xLocalReverse. Press the E-stop while running: the motor must stop no matter what the PLC says.
  4. From the panel: key ON, press Start (runs at iPanelSpeed), press Stop. Turn the key OFF while running: it stops and won’t restart until Start is pressed again.
  5. Raise iMaxSpeed to the demo limit: the motor’s nameplate speed or lower (about 1750 rpm for a 60 Hz 4-pole motor). Set the dashboard’s Setup → speed limit and nominal speed to match.

Dashboard

  1. Dashboard → IP addresses tab: check every device shows reachable. Setup → Mode Live. The heartbeat counts and all boxes on the network tab go green.
  2. To let the dashboard run the motor: tick Allow drive control in Setup, then set xDashboardAllowed TRUE in the PLC. The VFD control tab lists every permissive and shows which one is blocking.
  3. On the VFD control tab: Start forward, Stop, Start reverse, then hold Jog (the PLC caps it at iJogSpeedMax). Change the ramps and watch the reference-vs-actual chart.
  4. Run the demo sequence once with the motor uncoupled and a low iMaxSpeed. It uses the same command block as the buttons, so the PLC needs nothing extra. Check that STOP, the panel Stop and the E-stop each end it.
  5. Close the dashboard page while the motor runs: the PLC watchdog drops the run command within about 1 s.

9Confirm on your hardware

  • Which X80 I/O modules are on the drop, their instance names, and which channel each button and lamp is wired to. On our board: the second module with rotary switches next to the CRA, and the wired I/O module.
  • ATV930U07M3 supply is 200–240 V three-phase, the keypad is on Remote, and the motor nameplate suits a 4.6 A drive.
  • The drop’s health bit and the CPU’s RIO main-ring status bit (element names in the Data Editor).
  • BMENOC0301 backplane port enabled, and the laptop on ETH1 can reach the SIG200 and ATV930.
  • BMENUA0100: firmware and Control Expert version, the mode selector, and how the HMI flag exposes variables on your version.
  • Device-DDT element names for the SIG200 and ATV930 (health/Freshness bits, input and output elements).
  • Which SIG200 bit means “device present / process data valid on S1”, and the S1 byte offset.
  • MPB10 IODD: value offsets, scaling, and alarm-bit meanings.
  • ATV930 keypad menu names, the comms-fault parameter, and whether LCR/OTR/THR/LFT (and ACC/DEC on the output side) fit in the drive’s cyclic exchange.
  • The Modbus unit ID the M580 answers on (the dashboard defaults to 255; try 0 if it gets no reply).
